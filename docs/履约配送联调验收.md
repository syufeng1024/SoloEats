# 商家履约与骑手配送联调验收

> 接口前缀：`/api/v1/orders`
> 关联模块：`solo-eats-order`、`solo-eats-delivery`
> 测试环境：MySQL 3307、Redis 6379、RabbitMQ 5672
> 前置条件：订单已支付，且 `fulfillment_type = 1`（平台配送）

## 1. 接口清单

| 方法 | 路径 | 作用 | 订单状态变化 |
|---|---|---|---|
| POST | `/api/v1/orders/{orderId}/accept` | 商家接单 | `WAIT_ACCEPT(10) → PREPARING(20)` |
| POST | `/api/v1/orders/{orderId}/prepared` | 商家备餐完成 | `PREPARING(20) → WAIT_RIDER_PICKUP(30)` |
| POST | `/api/v1/orders/{orderId}/rider/accept` | 骑手接单 | 订单保持 `WAIT_RIDER_PICKUP(30)`，配送单 `0/10 → 20` |
| POST | `/api/v1/orders/{orderId}/rider/pickup` | 骑手到店取货 | `WAIT_RIDER_PICKUP(30) → DELIVERING(40)`，配送单 `20 → 40` |
| POST | `/api/v1/orders/{orderId}/rider/delivered` | 骑手送达 | `DELIVERING(40) → DELIVERED(50) → COMPLETED(60)`，配送单 `40 → 50` |

商家接口无请求体；骑手接口请求体：

```json
{ "riderId": 9001 }
```

## 2. 前置：下单与支付

创建配送单：

```powershell
curl.exe -X POST http://localhost:8080/api/v1/orders `
  -H "Content-Type: application/json; charset=UTF-8" `
  -H "Idempotency-Key: fulfillment-order-001" `
  -d '{
    "userId": 1,
    "merchantId": 1,
    "shopId": 1,
    "fulfillmentType": 1,
    "packagingFee": 200,
    "deliveryFee": 500,
    "receiverName": "Zhang San",
    "receiverPhone": "13800000000",
    "receiverAddress": "Test Road 1",
    "remark": "fulfillment test",
    "items": [ { "skuId": 1001, "quantity": 2 } ]
  }'
```

支付回调成功后，`OrderPaySuccessConsumer` 除了把订单流转到 `WAIT_ACCEPT(10)`，还会为平台配送订单创建 `t_delivery_order`：

| 字段 | 值 |
|---|---|
| `status` | 0（待派单） |
| `rider_id` | NULL |
| `delivery_fee` | 500 |
| `pickup_address` | `shop-1` |
| `receiver_address` | 下单地址 |

## 3. 履约流程与实测

订单：`orderId=5`，goods=5600，packaging=200，delivery=500，pay=6300。

### 3.1 商家接单

```powershell
curl.exe -X POST http://localhost:8080/api/v1/orders/5/accept
```

```json
{"code":0,"message":"ok","data":{"orderId":5,"status":20,"statusName":"备餐中"}}
```

### 3.2 商家备餐完成

```powershell
curl.exe -X POST http://localhost:8080/api/v1/orders/5/prepared
```

```json
{"code":0,"message":"ok","data":{"orderId":5,"status":30,"statusName":"待骑手取货"}}
```

### 3.3 骑手接单

```powershell
curl.exe -X POST http://localhost:8080/api/v1/orders/5/rider/accept `
  -H "Content-Type: application/json" `
  -d '{ "riderId": 9001 }'
```

```json
{"code":0,"message":"ok","data":{"orderId":5,"status":30,"statusName":"待骑手取货"}}
```

订单状态保持 30；配送单 `status=20`、`rider_id=9001`、`accepted_at` 写入。

### 3.4 骑手取货

```powershell
curl.exe -X POST http://localhost:8080/api/v1/orders/5/rider/pickup `
  -H "Content-Type: application/json" `
  -d '{ "riderId": 9001 }'
```

```json
{"code":0,"message":"ok","data":{"orderId":5,"status":40,"statusName":"配送中"}}
```

配送单 `status=40`、`picked_up_at` 写入。

### 3.5 骑手送达

```powershell
curl.exe -X POST http://localhost:8080/api/v1/orders/5/rider/delivered `
  -H "Content-Type: application/json" `
  -d '{ "riderId": 9001 }'
```

```json
{"code":0,"message":"ok","data":{"orderId":5,"status":60,"statusName":"已完成"}}
```

送达时在一个事务内完成：

1. 配送单 `40 → 50`，写 `delivered_at`；
2. 写 `t_rider_income`：`base_fee=500`、`total_amount=500`、`status=0`；
3. 订单 `40 → 50`（`RIDER_DELIVERED`）；
4. 订单 `50 → 60`（`AUTO_COMPLETE`）；
5. 写 `completed_at`、`settle_eligible_at = completed_at + 7 天`。

## 5. 状态机约束

| 操作 | 允许的订单状态 | 不满足时 |
|---|---|---|
| 商家接单 | `WAIT_ACCEPT(10)` | `ORDER_STATUS_INVALID` |
| 商家备餐完成 | `PREPARING(20)` | `ORDER_STATUS_INVALID` |
| 骑手接单 | `WAIT_RIDER_PICKUP(30)` | `ORDER_STATUS_INVALID` |
| 骑手取货 | `WAIT_RIDER_PICKUP(30)` | `ORDER_STATUS_INVALID` |
| 骑手送达 | `DELIVERING(40)` | `ORDER_STATUS_INVALID` |

配送单条件更新：

```sql
-- 接单
UPDATE t_delivery_order
SET rider_id = ?, status = 20, accepted_at = NOW(3), version = version + 1
WHERE order_id = ? AND status IN (0, 10) AND rider_id IS NULL;

-- 取货
UPDATE t_delivery_order
SET status = 40, picked_up_at = NOW(3), version = version + 1
WHERE order_id = ? AND rider_id = ? AND status = 20;

-- 送达
UPDATE t_delivery_order
SET status = 50, delivered_at = NOW(3), version = version + 1
WHERE order_id = ? AND rider_id = ? AND status = 40;
```

## 7. 已知边界

| 项 | 当前处理 |
|---|---|
| 商家操作人 | 商家接口无登录态，状态流水 `operator_id` 为 NULL；后续从登录上下文取 `merchantId` |
| 骑手身份 | 骑手 ID 由请求体传入，未接骑手登录与认证 |
| 派单 | 支付成功直接创建待派单配送单，尚未实现自动派单/抢单大厅；骑手可直接接单 |
| 骑手收入 | 只写基础配送费，距离/时段/天气补贴未接入 |
| 送达确认 | 骑手送达即自动完成，用户确认收货/自动完成计时未参与当前链路 |
| 自取订单 | 商家备餐完成后进入 `WAIT_USER_PICKUP(31)`，不进入骑手接口 |
