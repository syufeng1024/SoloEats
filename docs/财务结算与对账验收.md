# 商家财务结算与对账联调验收

> 接口前缀：`/api/v1/merchant/settlements`、`/api/v1/admin/settlements`
> 关联模块：`solo-eats-settlement`、`solo-eats-order`
> 测试环境：MySQL 3307、Redis 6379、RabbitMQ 5672

## 1. 接口清单

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/v1/merchant/settlements?merchantId=1&status=0` | 商家结算账单列表与汇总 |
| GET | `/api/v1/merchant/settlements/{billId}?merchantId=1` | 单笔账单明细与关联订单 |
| POST | `/api/v1/admin/settlements/generate` | 本地/测试触发结算（生产需加管理员鉴权） |

定时任务：

```yaml
app:
  settlement:
    bill-cron: "0 0 2 * * ?"
    default-commission-rate: 0.0600
```

## 2. 结算归集规则

参与结算的订单必须同时满足：

| 条件 | 值 |
|---|---|
| 订单状态 | `COMPLETED(60)` |
| 结算标记 | `settlement_status = 0` |
| 退款状态 | `refund_status = 0` |
| 已退金额 | `refunded_amount = 0` |
| 结算等待期 | `settle_eligible_at <= NOW()`，且非空 |

发生过退款或部分退款的订单直接排除；后续如需冲抵，应走下一期负项调整。

## 3. 计算口径

单个订单：

```text
gross              = goods_amount + packaging_fee
commission_base    = gross - merchant_discount
commission_amount  = round(commission_base × 0.0600)
merchant_amount    = gross - merchant_discount + platform_discount
                   - commission_amount
                   - performance_fee
                   - refund_amount
```

P0：

- `performance_fee = 0`
- `refund_amount = 0`（退款订单已剔除）
- 平台券金额进入 `platform_discount`，商家券进入 `merchant_discount`
- 配送费不进入商家结算，归平台/骑手侧

账单：

```text
gross_amount       = Σ 订单 gross
merchant_discount  = Σ 订单 merchant_discount
platform_discount  = Σ 订单 platform_discount
commission_base    = Σ 订单 commission_base
commission_amount  = Σ 订单 commission_amount
payable_amount     = Σ 订单 merchant_amount
```

## 4. 实测数据

### 4.1 参与结算的订单

订单 `orderId=12`，平台配送，商家券 3003，商品 5600 + 打包 200 + 配送 500 − 商家券 500 = 实付 5800。

| 字段 | 值 |
|---|---|
| goods_amount | 5600 |
| packaging_fee | 200 |
| delivery_fee | 500 |
| merchant_discount | 500 |
| platform_discount | 0 |
| pay_amount | 5800 |
| gross | 5800 |
| commission_base | 5300 |
| commission_amount | 318 |
| merchant_amount | 4982 |
| settlement_status | 1 |

### 4.2 被剔除的退款订单

订单 `orderId=13`，模拟已完成后退款：

| 字段 | 值 |
|---|---|
| status | 60 |
| refund_status | 2 |
| refunded_amount | 3000 |
| settlement_status | 0（未结算） |

该订单未进入账单。

### 4.3 结算账单

```json
{
  "billId": 1,
  "billNo": "SB202610211050212E33ADAB",
  "merchantId": 1,
  "billDate": "2026-10-21",
  "grossAmount": 5800,
  "merchantDiscount": 500,
  "platformDiscount": 0,
  "commissionBase": 5300,
  "platformCommission": 318,
  "merchantAmount": 4982,
  "performanceFee": 0,
  "refundAmount": 0,
  "status": 0
}
```

结算明细：

| orderId | itemType | amount | 说明 |
|---|---|---|---|
| 12 | 1 | 5300 | 商品+打包-商家优惠+平台补贴 |
| 12 | 2 | -318 | 平台佣金 |

明细合计：`5300 - 318 = 4982`，等于账单 `payable_amount`。

### 4.4 对账恒等式

```text
merchantAmount + platformCommission
= 4982 + 318
= 5300

userPayAmount - deliveryFee
= 5800 - 500
= 5300
```

结果一致。

## 5. 验证 SQL

```sql
SELECT id, status, settlement_status, refund_status, refunded_amount,
       goods_amount, packaging_fee, delivery_fee,
       merchant_discount, platform_discount, pay_amount
FROM t_order WHERE id IN (12, 13);

SELECT id, bill_no, merchant_id, bill_date, gross_amount, merchant_discount,
       platform_discount, commission_base, commission_amount,
       performance_fee, refund_amount, payable_amount, status
FROM t_settlement_bill WHERE id = 1;

SELECT order_id, item_type, amount, remark
FROM t_settlement_item WHERE bill_id = 1 ORDER BY id;

SELECT SUM(amount) FROM t_settlement_item WHERE bill_id = 1;
```

## 7. 已知边界

| 项 | 当前处理 |
|---|---|
| 佣金规则 | P0 使用全局默认 6%；尚未接商家/品类/活动三级费率 |
| 履约服务费 | P0 固定 0 |
| 退款冲抵 | 退款订单直接排除；已结算退款进下一期负项尚未实现 |
| 账单粒度 | 商家级账单，`shop_id` 为空；连锁多门店拆分未实现 |
| 结算触发 | 定时任务 02:00；测试用 `/api/v1/admin/settlements/generate`，未鉴权 |
| 账单审核/打款 | 账单状态只到 `GENERATED(0)`；审核、模拟打款未接 |
| 订单与账单关联 | `t_order` 没有 `settlement_bill_id`；通过 `t_settlement_item.order_id` 反查 |
| 退款订单测试 | 订单 13 为 SQL 模拟“已完成后退款”，用于验证排除条件 |
