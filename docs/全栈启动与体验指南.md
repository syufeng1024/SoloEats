# SoloEats 全栈启动与体验指南

适用版本：`master` 分支提交 `6e309da`。后端 Spring Boot 3.5.16 + MySQL 8 + Redis + RabbitMQ，前端 Vue 3 + Vite 6 + Element Plus。

## 1. 环境与端口

| 组件 | 要求 / 宿主机端口 | 检查命令 |
|---|---|---|
| Docker Desktop | WSL2 后端 | `docker version` |
| JDK | 17 | `java -version` |
| Maven | 3.9+ | `mvn -v` |
| Node.js | 20+ | `node -v` |
| 后端 | `8080` | `curl http://localhost:8080/healthz` |
| 前端（容器或开发服务器） | `5173` | `curl http://localhost:5173/nginx-health` |
| MySQL | 宿主机 `3307` → 容器 `3306` | `docker compose ps` |
| Redis | `6379` | `docker compose ps` |
| RabbitMQ | `5672` / 管理台 `15672` | `docker compose ps` |
| MinIO（Silo） | `9000` / 控制台 `9001` | `docker compose ps` |

MySQL 宿主机端口以 `docker compose ps` 实际输出为准；容器内后端通过服务名 `mysql:3306` 连接，不经过宿主机端口。

## 2. 启动后端

首次启动先准备环境变量：

```bash
cp .env.example .env
```

修改 `.env` 中的 MySQL、Redis、RabbitMQ、MinIO 密码与 `JWT_SECRET`，然后启动中间件和后端：

```bash
docker compose up -d mysql redis rabbitmq minio
docker compose build app
docker compose up -d app
```

前后端一次拉起（含 `web` 的 nginx 静态站）：

```bash
docker compose up -d --build
docker compose ps          # 6 个服务，app 与 web 均为 healthy
```

Maven 镜像被限速（实测 aliyun 约 5 KB/s）时，容器内多阶段构建会长时间停在依赖下载。改用宿主机缓存打包，再构建运行时镜像：

```bash
mvn -B -Dmaven.test.skip=true package
docker build -f Dockerfile.runtime -t solo-eats-app:latest \
  --build-arg JRE_IMAGE=docker.1ms.run/library/eclipse-temurin:17-jre-alpine \
  solo-eats-app/target
docker compose up -d app web
```

`Dockerfile.runtime` 的构建上下文是 `solo-eats-app/target`，只做 JRE 运行时封装；CI 仍使用根目录 `Dockerfile` 的多阶段构建。

修改后端代码后必须重建镜像，否则容器仍运行旧 jar：

```bash
docker compose build app
docker compose up -d --no-deps app
```

健康检查：

```bash
curl http://localhost:8080/healthz   # 进程存活，不访问外部依赖
curl http://localhost:8080/readyz    # 200 表示 MySQL / Redis / RabbitMQ 均就绪
```

`/readyz` 返回 503 时：

```bash
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 mysql
```

本地 Maven 启动方式：

```bash
mvn -pl solo-eats-app -am spring-boot:run
```

本地启动时 `MYSQL_HOST=localhost`、`MYSQL_PORT` 必须指向 Compose 暴露的宿主机端口（当前为 `3307`）。如果 `.env` 仍写 `3306`，会连不上数据库。

## 3. 启动前端

容器方式（与后端同一 Compose 栈）：

```bash
docker compose up -d --build web
```

访问 `http://localhost:5173`。`solo-eats-web/Dockerfile` 用 Node 20 执行 `npm run build`，产物交给 nginx；`solo-eats-web/nginx.conf` 把 `/api/` 反代到 `app:8080`，`createWebHistory` 路由回退到 `index.html`。改前端代码后必须重建镜像。

本地开发方式：

```bash
cd solo-eats-web
npm install
npm run dev
```

前端开发服务器把 `/api` 代理到 `http://localhost:8080`，浏览器只访问同源地址。后端 `WebMvcConfig` 没有配置 CORS，**不要把 `VITE_API_BASE_URL` 改成跨域地址**，否则浏览器会拦截请求。

## 4. 登录

登录接口 `POST /api/v1/auth/login` 由 `AuthController` 上的 `@Profile("local")` 提供，不校验密码，只按角色签发 JWT。

| 角色 | 填写内容 | 说明 |
|---|---|---|
| 商家 | 商家 ID `1`，门店 ID `1` | 对应 `V2__sku_and_demo_data.sql` 的演示 SKU |
| 平台管理员 | 用户 ID 留空或 `0` | 后端缺省按 `0` 签发 |

Token 有效期 120 分钟，存储在 `localStorage` 的 `solo-eats.auth`。收到 HTTP 401 或业务码 `10003` 会清空登录态并跳回登录页。

## 5. 商家端体验路径

| 页面 | 可执行操作 | 后端接口 |
|---|---|---|
| 订单管理 | 状态分栏、订单号/收货人/手机号检索、接单、备餐完成、拒单、商家取消、呼叫骑手 | `GET /api/v1/merchant/orders`、`POST /api/v1/orders/{id}/accept`、`/prepared`、`/reject`、`/cancel`、`/merchant/call-rider` |
| 商品与库存 | 新增 SKU、编辑价格/规格/上下架、维护可售库存与估清 | `GET/POST /api/v1/merchant/skus`、`PUT /api/v1/merchant/skus/{skuId}`、`PUT /api/v1/merchant/skus/{skuId}/stock` |
| 财务结算 | 账单汇总、状态筛选、账单号过滤、明细抽屉 | `GET /api/v1/merchant/settlements`、`GET /api/v1/merchant/settlements/{billId}` |

状态流转：

```text
接单      WAIT_ACCEPT(10)  → PREPARING(20)
备餐完成  PREPARING(20)    → WAIT_RIDER_PICKUP(30) 或 WAIT_USER_PICKUP(31)
拒单      WAIT_ACCEPT(10)  → CANCELLED(70)，触发退款
呼叫骑手  配送单 0/10/71    → 10，dispatch_count + 1
```

商家呼叫骑手不会改变订单状态；骑手接单仍走 `POST /api/v1/orders/{id}/rider/accept`（仅 `RIDER` 角色，必填 `riderId`）。

## 6. 平台端体验路径

| 页面 | 可执行操作 | 后端接口 |
|---|---|---|
| 运营看板 | 按商家/门店/状态/日期/关键字筛选，查看状态计数、实付、退款汇总 | `GET /api/v1/admin/orders/monitor` |
| 抽成结算 | 跨商家账单分页、佣金与应结合计、按状态/日期筛选、生成当日账单 | `GET /api/v1/admin/settlements/stats`、`POST /api/v1/admin/settlements/generate` |

管理端订单列表的收件手机号按 `前 3 位 + **** + 后 4 位` 脱敏。商家端订单列表保留完整联系方式，用于履约。

佣金口径：

```text
佣金基数 = goods_amount + packaging_fee - merchant_discount
平台佣金 = round(佣金基数 × commissionRate)
商家应结 = goods_amount + packaging_fee - merchant_discount + platform_discount - 平台佣金
```

`commissionRate` 默认 `0.0600`，对应 `app.settlement.default-commission-rate`。同一商家同一天只生成一张账单，由 `uk_merchant_date` 保证。

## 7. 造一笔可体验订单

当前库保留了一笔已完成订单 22 和账单 2，可以直接登录商家 1 / 管理员查看。需要重新造数时按以下顺序执行。

### 7.1 创建订单

```bash
UT=$(curl -s -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"role":"C_USER","userId":1}' \
  | node -pe "JSON.parse(require('fs').readFileSync(0,'utf8')).data.token")

printf '%s' '{"userId":1,"merchantId":1,"shopId":1,"fulfillmentType":1,"packagingFee":200,"deliveryFee":500,"receiverName":"联调用户","receiverPhone":"13800001234","receiverAddress":"测试路1号","remark":"manual demo","items":[{"skuId":1001,"quantity":1}]}' > /tmp/order.json

curl -s -X POST http://localhost:8080/api/v1/orders \
  -H "Authorization: Bearer $UT" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: demo-$(date +%s)" \
  --data-binary @/tmp/order.json
```

### 7.2 支付并回调

```bash
OID=<上一步返回的 orderId>

PAY=$(curl -s -X POST http://localhost:8080/api/v1/payments/pay \
  -H "Authorization: Bearer $UT" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: demo-pay-$(date +%s)" \
  -d "{\"orderId\":$OID,\"channel\":3}")

PAYNO=$(echo "$PAY" | node -pe "JSON.parse(require('fs').readFileSync(0,'utf8')).data.paymentNo")
AMT=$(echo "$PAY" | node -pe "JSON.parse(require('fs').readFileSync(0,'utf8')).data.amount")
SECRET=$(grep -E '^PAYMENT_CALLBACK_SECRET=' .env | head -1 | cut -d= -f2- | tr -d '\r')
TRADE="TRADE-DEMO-$(date +%s)"
SIGN=$(node -e "const c=require('crypto');process.stdout.write(c.createHmac('sha256',process.argv[1]).update(process.argv[2]+':'+process.argv[3]+':'+process.argv[4]).digest('hex'))" "$SECRET" "$PAYNO" "$TRADE" "$AMT")

curl -s -X POST http://localhost:8080/api/v1/payments/callback \
  -H 'Content-Type: application/json' \
  -d "{\"paymentNo\":\"$PAYNO\",\"tradeNo\":\"$TRADE\",\"amount\":$AMT,\"sign\":\"$SIGN\"}"
```

回调后由 RabbitMQ 消费把订单置为 `WAIT_ACCEPT(10)`，通常 1 秒内完成。商家订单页如果没有出现，点击刷新。

### 7.3 商家与骑手履约

1. 商家登录，订单管理页点击“接单”“备餐完成”。
2. 配送单点击“呼叫骑手”，返回 `deliveryNo`、`dispatchCount`、`dispatchExpireAt`。
3. 骑手登录：`{"role":"RIDER","riderId":77}`，依次调用 `/rider/accept`、`/rider/pickup`、`/rider/delivered`。
4. 订单变为 `COMPLETED(60)`，`settle_eligible_at` 默认为完成时间 + 7 天。

### 7.4 立即生成结算账单

完成订单默认 7 天后可结算。需要立即体验时，把指定订单的可结算时间调到过去：

```bash
PW=$(grep -E '^MYSQL_PASSWORD=' .env | head -1 | cut -d= -f2- | tr -d '\r')
docker exec -i solo-eats-mysql mysql -usolo -p"$PW" solo_eats \
  -e "UPDATE t_order SET settle_eligible_at = DATE_SUB(NOW(3), INTERVAL 1 DAY) WHERE id=$OID;"
```

然后管理员登录，抽成结算页点击“生成当日账单”。也可直接执行已有脚本：

```bash
bash scripts/settlement-smoke-test.sh
bash scripts/refund-smoke-test.sh
```

## 10. 数据库与迁移

- 全新空库：`FLYWAY_ENABLED=true`，Flyway 依次执行 `V1__init_schema.sql`、`V2__sku_and_demo_data.sql`、`V3__merchant_order_query_index.sql`。
- 已有库：通常 `FLYWAY_ENABLED=false`，需要手动执行新增迁移。当前环境已执行 V3：

```sql
CREATE INDEX idx_merchant_status_created
    ON t_order (merchant_id, status, created_at);
```

- 禁止直接修改已有列或删除列；新增字段/索引一律新建迁移文件，并保证旧代码可运行。

## 11. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 登录返回 404 | 当前不是 `local` profile | 设置 `SPRING_PROFILES_ACTIVE=local` 后重启 |
| 401 / 业务码 10003 | Token 过期或未携带 | 重新登录；Axios 会自动附加 Bearer |
| 403 / 业务码 10004 | 角色不符，或 merchantId / shopId 与 JWT 不一致 | 用对应角色重新登录 |
| 404 / 业务码 20002 | 订单不存在 | 确认 orderId |
| 409 / 业务码 20001 | 订单状态不允许当前操作 | 刷新列表，按状态机顺序操作 |
| `/readyz` 503 | MySQL / Redis / RabbitMQ 未就绪 | 查看 `docker compose ps` 与容器日志 |
| 浏览器 CORS 报错 | 绕过 Vite 代理直连 8080 | 使用 `npm run dev` 的 `/api` 代理或同源 Nginx |
| 刷新前端子路由 404 | Nginx 未配置 history 回退 | 加 `try_files $uri $uri/ /index.html;` |
| 容器内仍是旧接口 | 只改了源码，没有重建镜像 | `docker compose build app && docker compose up -d --no-deps app` |
