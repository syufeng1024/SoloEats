# 数创星光外卖 · 本地开发环境搭建指南

> 适用：Windows 11 + Docker Desktop（WSL2 后端）+ JDK 17 + Maven 3.9
> 关联：[技术架构与数据库设计说明书](技术架构与数据库设计说明书.md)
> 目标：启动 MySQL / Redis / RabbitMQ / MinIO（Silo 兼容实现），初始化 22 张 P0 核心表，跑通 Spring Boot 3 模块化单体骨架

## 1. 前置条件

| 工具 | 版本 | 检查命令 |
|---|---|---|
| Docker Desktop | 4.x，启用 WSL2 | `docker version` |
| Docker Compose | V2 | `docker compose version` |
| JDK | 17 | `java -version` |
| Maven | 3.9+ | `mvn -v` |
| Node.js | 18+（前端阶段再用） | `node -v` |
| Git | 任意 | `git --version` |

Docker Desktop 未启动时，`docker compose` 会报 `cannot connect to the Docker daemon`，先启动 Docker Desktop 并等待鲸鱼图标变绿。

## 3. 配置环境变量

PowerShell：

```powershell
Copy-Item .env.example .env
notepad .env
```

必须修改的项：

| 变量 | 用途 | 建议 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码 | 本地随机字符串，至少 12 位 |
| `MYSQL_PASSWORD` | 应用账号 `solo` 密码 | 与 `MYSQL_ROOT_PASSWORD` 不同 |
| `REDIS_PASSWORD` | Redis 密码 | 本地随机字符串 |
| `RABBITMQ_PASSWORD` | RabbitMQ 密码 | 本地随机字符串 |
| `MINIO_ROOT_USER` | MinIO / Silo 账号 | 至少 3 位 |
| `MINIO_ROOT_PASSWORD` | MinIO / Silo 密码 | 至少 8 位 |
| `JWT_SECRET` | JWT 签名密钥 | 至少 32 字节 |
| `REGISTRY_PREFIX` | Docker 镜像前缀 | 国内网络填 `docker.m.daocloud.io/`；可直连 Docker Hub 时留空 |
| `SILO_IMAGE` | MinIO 兼容镜像 | 默认 `docker.m.daocloud.io/pgsty/silo:RELEASE.2026-09-16T00-00-00Z` |

`.env` 已被 `.gitignore` 忽略，不要提交。`docker-compose.yml` 对密码使用 `${VAR:?}`，缺少 `.env` 或变量为空时直接报错，不会用默认弱密码启动。

## 4. 启动中间件

```powershell
docker compose up -d
```

查看状态：

```powershell
docker compose ps
```

四个服务都应为 `running` / `healthy`：

| 服务 | 容器名 | 端口 | 健康检查 |
|---|---|---|---|
| MySQL | `solo-eats-mysql` | 3307 | `mysqladmin ping` |
| Redis | `solo-eats-redis` | 6379 | `redis-cli ping` |
| RabbitMQ | `solo-eats-rabbitmq` | 5672 / 15672 | `rabbitmq-diagnostics ping` |
| MinIO（Silo） | `solo-eats-minio` | 9000 / 9001 | `silo healthcheck ready` |

首次启动 MySQL 需要 30~60 秒。查看日志：

```powershell
docker compose logs -f mysql
docker compose logs -f minio
```

### 4.1 连接信息

| 中间件 | 地址 | 账号 | 说明 |
|---|---|---|---|
| MySQL | `127.0.0.1:3307` | `solo` / `.env` 中 `MYSQL_PASSWORD` | 数据库 `solo_eats`，字符集 `utf8mb4`；3306 被本机 MySQL 占用 |
| Redis | `127.0.0.1:6379` | 密码 `.env` 中 `REDIS_PASSWORD` | AOF 持久化 |
| RabbitMQ | `127.0.0.1:5672` | `.env` 中 `RABBITMQ_USER` / `RABBITMQ_PASSWORD` | vhost `/` |
| RabbitMQ 管理台 | http://localhost:15672 | 同上 | 管理插件已启用 |
| MinIO / Silo API | http://localhost:9000 | `.env` 中 `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` | S3 兼容 |
| MinIO / Silo 控制台 | http://localhost:9001 | 同上 | 桶 `solo-eats` 需手动创建 |

上表是**宿主机**访问地址。若后端也放进 Compose，主机名改为服务名：`mysql`、`redis`、`rabbitmq`、`minio`。

**镜像说明**：MinIO 官方 Docker 镜像已在 2026 年从 Docker Hub 下架，Compose 改用兼容 fork `pgsty/silo`，它保留 `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD`、9000/9001 端口和 S3 API。国内网络通过 `.env` 的 `REGISTRY_PREFIX` 走 DaoCloud 镜像；如果 Docker Hub 可直连，把 `REGISTRY_PREFIX` 留空即可。

### 4.2 创建 bucket

Silo 不再自动建桶。首次启动后：

1. 打开 http://localhost:9001
2. 用 `.env` 中的 `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` 登录
3. 创建 bucket：`solo-eats`
4. 保持私有访问，应用通过预签名 URL 或服务端代理访问

后端启动前必须存在该 bucket，否则上传接口会报 `NoSuchBucket`。

快速验证：

```powershell
docker exec -it solo-eats-redis redis-cli -a <REDIS_PASSWORD> ping
docker exec -it solo-eats-mysql mysql -usolo -p<MYSQL_PASSWORD> -e "SELECT VERSION(), @@character_set_server, @@collation_server;"
```

## 5. 初始化数据库

`V1__init_schema.sql` 位于 `solo-eats-app/src/main/resources/db/migration/`，包含 22 张表：订单、明细、优惠快照、状态流水、库存、库存锁定、库存流水、券模板、用户券、券流水、支付单、退款单、退款明细、配送单、派单记录、异常池、结算账单、结算明细、骑手收入、提现单、幂等表、Outbox。

### 5.1 方式 A：Flyway（推荐）

1. 在 `.env` 中保持：

```properties
FLYWAY_ENABLED=true
FLYWAY_LOCATIONS=classpath:db/migration
```

2. 启动后端后，Flyway 自动执行 `V1__init_schema.sql`。
3. 验证：

```powershell
docker exec -it solo-eats-mysql mysql -usolo -p<MYSQL_PASSWORD> -e "USE solo_eats; SHOW TABLES;"
```

应看到 22 张业务表，以及 `flyway_schema_history`。

### 5.2 方式 B：手动执行

PowerShell：

```powershell
Get-Content .\solo-eats-app\src\main\resources\db\migration\V1__init_schema.sql -Raw |
  docker exec -i solo-eats-mysql mysql -usolo -p<MYSQL_PASSWORD> solo_eats
```

Git Bash：

```bash
docker exec -i solo-eats-mysql mysql -usolo -p<MYSQL_PASSWORD> solo_eats \
  < solo-eats-app/src/main/resources/db/migration/V1__init_schema.sql
```

手动执行后，把 `.env` 改为：

```properties
FLYWAY_ENABLED=false
```

否则 Flyway 会再次执行 V1，因表已存在而失败。

> 不要在同一个库上同时用 Flyway 和手动初始化。二选一。需要重来时：
> `docker compose down -v` 会删除所有数据卷，慎用。

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `port is already allocated` | 3307/6379/5672/9000 被占用 | 改 `.env` 中端口；本机 3306 已被 MySQL 服务占用 |
| `cannot connect to the Docker daemon` | Docker Desktop 未启动 | 启动 Docker Desktop |
| `pull access denied` / `connection timed out` | Docker Hub 不可达，或 MinIO 官方镜像已下架 | 保持 `REGISTRY_PREFIX=docker.m.daocloud.io/`；MinIO 使用 `SILO_IMAGE` 指向 `pgsty/silo` |
| `NoSuchBucket` | 未创建 `solo-eats` bucket | 打开 http://localhost:9001 创建 bucket |
| `Public Key Retrieval is not allowed` | MySQL 8 认证 | URL 已带 `allowPublicKeyRetrieval=true&useSSL=false` |
| Flyway 报表已存在 | 手动初始化后又开启 Flyway | `FLYWAY_ENABLED=false`，或重建数据卷 |
| Redis 连接池报 `commons-pool2` 缺失 | 未加依赖 | 加 `org.apache.commons:commons-pool2` |
| 应用读不到 `.env` | IDE 工作目录不对 | 设置 Working directory 为项目根目录，或配置系统环境变量 |
| 中文乱码 | 连接字符集不对 | JDBC URL 已带 `characterEncoding=utf8`；建库用 `utf8mb4` |
| 时间差 8 小时 | 时区未设置 | MySQL 容器 `+08:00`，JDBC `serverTimezone=Asia/Shanghai` |

## 9. 常用命令

```powershell
# 启动
docker compose up -d

# 停止，保留数据
docker compose down

# 停止并删除数据卷（会清空 MySQL/Redis/RabbitMQ/MinIO-Silo）
docker compose down -v

# 查看日志
docker compose logs -f mysql
docker compose logs -f redis
docker compose logs -f rabbitmq
docker compose logs -f minio

# 进入 MySQL
docker exec -it solo-eats-mysql mysql -usolo -p solo_eats
```
