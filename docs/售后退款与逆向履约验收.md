# 售后退款与逆向履约联调验收

> 接口前缀：`/api/v1/orders`
> 关联模块：`solo-eats-order`、`solo-eats-payment`、`solo-eats-product`、`solo-eats-marketing`
> 测试环境：MySQL 3307、Redis 6379、RabbitMQ 5672

## 1. 接口清单

| 方法 | 路径 | 作用 | 允许的订单状态 |
|---|---|---|---|
| POST | `/api/v1/orders/{orderId}/cancel` | 用户/商家主动取消 | `WAIT_PAY` / `WAIT_ACCEPT` / `PREPARING` / 已取消 |
| POST | `/api/v1/orders/{orderId}/refund` | 用户申请全额退款 | `WAIT_ACCEPT` / `PREPARING` |
| POST | `/api/v1/orders/{orderId}/reject` | 商家拒单并全额退款 | `WAIT_ACCEPT` |

三个接口都要求 `Idempotency-Key` 请求头。

请求体：

```json
// cancel
{ "reason": "user cancel unpaid", "operatorType": 1 }

// refund
{ "reason": "user changed mind" }

// reject
{ "reason": "out of stock", "merchantId": 1 }
```

`operatorType`：1 用户、2 商家。

## 2. 取消与退款规则

| 场景 | 处理 |
|---|---|
| `WAIT_PAY` 取消 | 不创建退款单；释放库存锁定；释放优惠券；订单 `0 → 70 CANCEL` |
| `WAIT_ACCEPT` / `PREPARING` 取消 | 走全额退款流程；订单最终 `70` |
| 用户退款 | 只允许 `WAIT_ACCEPT` / `PREPARING`；全额退款 |
| 商家拒单 | 只允许 `WAIT_ACCEPT`；全额退款；状态流水事件为 `MERCHANT_REJECT` |
| 已取消重复请求 | 返回最近退款信息，不重复退款 |

## 3. 退款处理流程

```text
RefundService
  -> 校验订单状态与支付成功记录
  -> 写 t_refund_order（REFUNDING=20）
  -> 按 t_order_item 写 t_refund_item（qty、payable_amount、restock_flag=1）
  -> 调用 PaymentGateway.refund（MockPaymentGateway）
      -> t_payment_order.status 20 -> 60
      -> 返回 MOCKREF-<refundNo>
  -> t_refund_order.status 20 -> 30，写 channel_refund_no、success_at
  -> StockService.refund：sold_qty -> available_qty，stock_lock 1 -> 3，写 REFUND 流水
  -> CouponService.rollback：券 2 -> 0（过期则 2 -> 5）
  -> 订单状态机：
       用户退款/取消：REFUND_FULL_SUCCESS -> CANCELLED(70)
       商家拒单：MERCHANT_REJECT -> CANCELLED(70)
  -> t_order_item 全部置为已退
  -> t_order：payment_status=2、refund_status=2、refunded_amount=实付
```

退款服务使用 `lock:refund:order:{orderId}` 分布式锁 + `TransactionTemplate`，同一订单不会并发退款；`t_refund_order.idempotency_key` 唯一，重复请求返回首次退款结果。

## 4. 实测结果

### 4.1 支付后未接单退款

订单 A：`orderId=9`，自取，商品 5600 + 打包 200 - 平台券 500 = 实付 5300。

| 项 | 结果 |
|---|---|
| 退款响应 | refundNo=`RF202610211026390F231A00`，amount=5300，refundStatus=30，orderStatus=70 |
| `t_order` | status=70，payment_status=2，refund_status=2，refunded_amount=5300 |
| `t_payment_order` | status=60（REFUNDED） |
| `t_refund_order` | amount=5300，status=30，channel_refund_no=`MOCKREF-RF202610211026390F231A00` |
| `t_refund_item` | qty=2，refund_amount=5100，restock_flag=1 |
| `t_sku_stock` | available=100，locked=0，sold=0 |
| `t_user_coupon` 3001 | status=0，order_id=NULL |
| 库存流水 | `LOCK 100→98`、`CONFIRM 98→98`、`REFUND 98→100` |
| 状态流水 | `0→10 PAY_SUCCESS`、`10→70 REFUND_FULL_SUCCESS` |
| 重复退款 | 同一幂等键返回同一 refundId/refundNo，库存不重复回补 |

### 4.2 商家拒单退款

订单 B：`orderId=10`，自取，无券，实付 5800。

|---|---|

| `t_order` | status=70，payment_status=2，refund_status=2，refunded_amount=5800 |
| `t_payment_order` | status=60 |
| `t_refund_order` | amount=5800，status=30 |
| `t_sku_stock` | available=100，locked=0，sold=0 |
| 状态流水 | `0→10 PAY_SUCCESS`、`10→70 MERCHANT_REJECT` |

### 4.3 未支付取消

订单 C：`orderId=11`，未支付。

| 项 | 结果 |
|---|---|
| 取消响应 | orderStatus=70，refundNo=null，refundAmount=0 |

## 5. 验证 SQL

```sql
SELECT id, status, payment_status, refund_status, refunded_amount, pay_amount
FROM t_order WHERE id = <orderId>;

SELECT payment_no, status FROM t_payment_order WHERE order_id = <orderId>;

SELECT refund_no, order_id, refund_type, amount, status, channel_refund_no
FROM t_refund_order WHERE order_id = <orderId>;

SELECT order_item_id, qty, refund_amount, restock_flag
FROM t_refund_item WHERE refund_id = <refundId>;

SELECT sku_id, available_qty, locked_qty, sold_qty

SELECT id, status, order_id FROM t_user_coupon WHERE id = 3001;

SELECT biz_type, biz_id, sku_id, op, qty, before_available, after_available
FROM t_stock_log WHERE biz_id = <orderId> ORDER BY id;

SELECT order_id, from_status, to_status, event
FROM t_order_status_log WHERE order_id = <orderId> ORDER BY id;
```

## 7. 已知边界

| 项 | 当前处理 |
|---|---|
| 退款网关 | MockPaymentGateway 同步返回成功；生产应改为“退款单落库 → 调用网关 → 回调更新”的跨事务流程 |
| 退款类型 | 只实现全额退款；部分退款、按商品退款未接 |
| 退款时机 | 只允许 `WAIT_ACCEPT` / `PREPARING`；骑手取货后需走单独的售后仲裁 |
| 已支付订单取消 | `/cancel` 的 `WAIT_ACCEPT` / `PREPARING` 分支复用全额退款；本次联调覆盖 `/refund` 与 `/reject`，未单独重复跑 `/cancel` 已支付分支 |
| 已制作商品 | 退款时统一回补库存，未按 `restock_flag` 区分食品是否可回库 |
| 订单取消时间 | 未支付取消写 `cancel_reason` / `cancelled_at`；退款/拒单路径以 `t_refund_order` 为凭证，未回写订单取消原因 |
| 消息 | 退款为同步编排，未发 RabbitMQ 售后事件 |
