| `PaymentServiceImplTest` | payment | 8 | 同幂等键返回既有支付单；非待支付拒绝；回调验签、金额校验、重复回调幂等 | 签名错误不落支付状态、不发布事件 |
| `OrderLifecycleIntegrationTest` | app | 7 | 真实 MySQL 下的下单锁库存、支付回调与 MQ 编排、商家接单、全额退款、退款网关失败事务回滚、自取完成、超时释放 | 取消后接单抛 `ORDER_STATUS_INVALID`；网关失败后 `t_refund_order`/`t_refund_item` 不得残留 |

运行命令：

```powershell
# Windows Docker Desktop 29 必须显式指定管道，否则 Testcontainers 报 400 + 空 Info
$env:DOCKER_HOST = "npipe:////./pipe/dockerDesktopLinuxEngine"
mvn -Pisolated-build clean test
```

`isolated-build` 把输出写到各模块 `target-mvn/`。VSCode 的 Red Hat Java 语言服务器会并发写 `target/classes`，与 Maven 构建冲突；该 profile 用于本地全量测试，CI 不需要。

## 3. 集成测试环境

| 组件 | 配置 | 说明 |
|---|---|---|
| MySQL | `mysql:8.0.46`，`TZ=Asia/Shanghai`，`--default-time-zone=+08:00` | 本地镜像由 `docker.m.daocloud.io/library/mysql:8.0` 打标签；避免时区导致的优惠券/结算断言偏差 |
| Flyway | `enabled=true`，`locations=classpath:db/migration` | 容器内空库执行 V1+V2 |
| Redis | 不启动容器，`@MockBean StringRedisTemplate` | `IdempotentAspect` 的 `setIfAbsent` 固定返回 `true` |
| RabbitMQ | 排除 `RabbitAutoConfiguration`，`@MockBean RabbitTemplate` | `@RabbitListener` 不注册；支付成功编排由测试直接调用 `handlePaySuccess` |
| Redisson | 排除 `RedissonAutoConfigurationV2`，`@MockBean DistributedLock` | 锁替身直接执行 `Supplier`，不连接 Redis |
| 事务 | 测试不加 `@Transactional` | 每例 `TRUNCATE` 业务表并重置 `t_sku_stock`、`t_user_coupon`，保证 `AFTER_COMMIT` 事件可触发 |
| Docker API | `src/test/resources/docker-java.properties`：`api.version=1.44` | Docker Engine 29 最低 API 为 1.40/1.44 |

## 4. 容器化

### 4.1 镜像

| 阶段 | 基础镜像 | 关键动作 |
|---|---|---|
| build | `${MAVEN_IMAGE}`，默认 `maven:3.9-eclipse-temurin-17` | 可选注入 `MAVEN_MIRROR_URL`；`mvn -B -Dmaven.test.skip=true package`；构建期不跑测试（无 Docker daemon） |
| runtime | `${JRE_IMAGE}`，默认 `eclipse-temurin:17-jre-alpine` | `apk upgrade`；创建非 root `app` 用户；`COPY --chown=app:app` |

运行时参数：`JAVA_OPTS` 默认 `-XX:MaxRAMPercentage=70 -XX:+UseG1GC -Duser.timezone=Asia/Shanghai`。`ENTRYPOINT ["sh","-c","exec java $JAVA_OPTS -jar /app/app.jar"]` 保证 SIGTERM 直达 JVM，配合 `server.shutdown=graceful`。

`.dockerignore` 排除 `.env`、`**/target`、`**/src/test`、`docs`、`scripts`、`.git`，避免密码与 JWT 密钥进入构建上下文。

### 4.2 Compose 接线

| 变量 | app 容器值 | 原因 |
|---|---|---|
| `MYSQL_HOST` / `MYSQL_PORT` | `mysql` / `3306` | `.env` 的 `MYSQL_PORT=3307` 是宿主机映射端口，容器内必须覆盖 |
| `REDIS_HOST` / `REDIS_PORT` | `redis` / `6379` | 服务名寻址 |
| `RABBITMQ_HOST` / `RABBITMQ_PORT` | `rabbitmq` / `5672` | 服务名寻址 |
| `MINIO_ENDPOINT` | `http://minio:9000` | 容器内地址 |
| `FLYWAY_ENABLED` | `${FLYWAY_ENABLED:-false}` | 默认关闭，避免对已有库误迁移；全新数据卷在 `.env` 显式设为 `true` |
| `LOG_LEVEL_SOLOEATS` | `${LOG_LEVEL_SOLOEATS:-INFO}` | 生产 INFO；本地 `.env` 设 DEBUG 才打印 SQL 参数 |
| `APP_PORT` | `${APP_PORT:-8080}` | 宿主机端口 |
| `MANAGEMENT_PORT` | 默认 `8081`，不发布 | Actuator 仅在容器网络内可达 |

`depends_on` 对 MySQL、Redis、RabbitMQ、MinIO 使用 `condition: service_healthy`；app 自身健康检查调用 `/readyz`，失败返回 503，容器状态转为 `unhealthy`。

### 4.3 一键部署与验证

```powershell
docker compose build app
docker compose up -d app
docker compose ps
curl.exe http://127.0.0.1:8080/healthz
curl.exe http://127.0.0.1:8080/readyz
python scripts/container-smoke-test.py
```

`container-smoke-test.py` 只依赖 Python 标准库与 `docker exec`，覆盖 JWT 登录、Redis 限流、下单、支付、HMAC 回调、RabbitMQ 消费、商家接单与退款。脚本支持 `MYSQL_USER`、`MYSQL_DATABASE`、`MYSQL_CONTAINER` 覆盖；密码通过容器内 `MYSQL_PWD` 传入，不出现在宿主机命令行。

### 4.4 CI 门禁

`.github/workflows/ci.yml` 在 push/PR 上执行：

1. `mvn -B -Pisolated-build clean test`，包含 6 个 Testcontainers 集成测试。
2. 扫描 `*/target-mvn/surefire-reports/*.txt`，出现 `Skipped: [1-9]` 直接失败，防止 Docker 不可用时集成测试静默跳过。
3. `docker build -t solo-eats-app:ci .`，验证镜像可构建；镜像构建阶段不跑测试。

## 5. 探针语义

| 端点 | 检查内容 | 成功 | 失败 |
|---|---|---|---|
| `GET /healthz` | 仅进程与 HTTP 线程存活，不访问任何依赖 | 200 `{"status":"UP","service":"solo-eats",...}` | 进程退出，无响应 |
| `GET /readyz` | Actuator `readiness` 组内全部组件 | 仅聚合状态与所有组件均 `UP` 返回 200 | 任一 `UNKNOWN`/`OUT_OF_SERVICE`/`DOWN` 返回 503；公开响应只含聚合状态，组件明细写日志 |
| `GET /actuator/health` | Actuator 聚合，仅监听 `8081` 管理端口 | 200 | 不对外发布，`show-details=never` |

`/readyz` 实际返回：

```json
{"status":"UP","timestamp":"2026-10-21T15:27:28.610816375+08:00"}
```

Actuator 仅暴露 `health,info`，监听 `MANAGEMENT_PORT=8081` 且不在 Compose 中发布；`show-details` 设为 `never`，依赖详情统一由 `/readyz` 提供。

## 9. 已知限制

1. Windows Docker Desktop 29 + Testcontainers 必须设置 `DOCKER_HOST=npipe:////./pipe/dockerDesktopLinuxEngine`；否则报 `Status 400` 与空 `Info`。
2. VSCode Red Hat Java 语言服务器与 Maven 并发写 `target/classes`；本地全量测试使用 `-Pisolated-build`。
3. 集成测试标注 `@Testcontainers(disabledWithoutDocker = true)`；无 Docker 的 CI 会显示 6 个 skipped，必须把 skipped 数纳入门禁，避免假绿。
4. `V2__sku_and_demo_data.sql` 只补齐缺失的演示行，重复键为 no-op；生产库仍建议移除该脚本。
5. 当前 `.env` 的 `MYSQL_PORT=3307` 只适用于宿主机运行；容器内由 Compose 显式覆盖为 3306。
6. `.env` 的 `LOG_LEVEL_SOLOEATS=DEBUG` 会打印 SQL 参数与收货信息；生产必须设为 `INFO`。
7. Actuator 管理端口 `8081` 默认不发布；若监控系统需要采集，单独暴露并加访问控制，不要复用 8080。
8. `mem_limit`/`cpus` 是单机 Compose 的约束；生产编排应改为 Kubernetes `requests/limits`。

参考：[Red Hat CVE-2026-47884](https://bugzilla.redhat.com/show_bug.cgi?id=CVE-2026-47884)、[Tenable 341190](https://www.tenable.com/plugins/nessus/341190)、[FINERACT-2962](https://issues.apache.org/jira/browse/FINERACT-2962)。
